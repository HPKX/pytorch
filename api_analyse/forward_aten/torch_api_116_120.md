# torch API 116-120 ATen Dispatch 分析

| 接口 | 场景 | ATen Dispatch 调用链 | 正向 Dispatch 依赖的 ATen 接口 |
| --- | --- | --- | --- |
| `torch.nn.MultiLabelSoftMarginLoss` | 常规前向（可选 `weight`，`reduction='mean'`） | `Module.forward -> F.multilabel_soft_margin_loss`（Python 组合，不对应单一 loss schema）`-> aten::log_sigmoid(input)` 与 `aten::neg(input) -> aten::log_sigmoid(-input)`；两次 `aten::log_sigmoid` 都经 `CompositeImplicitAutograd` 包装并进入 `aten::log_sigmoid_forward -> CPU/CUDA/MPS kernel`；随后做 `aten::rsub.Scalar(1, target) -> aten::mul -> aten::add -> aten::neg`，若有 `weight` 再乘权重，最后 `aten::sum(dim=class) -> aten::div.Scalar -> aten::mean` | `aten::log_sigmoid`, `aten::neg`, `aten::log_sigmoid_forward`, `aten::rsub.Scalar`, `aten::mul`, `aten::add`, `aten::sum`, `aten::div.Scalar`, `aten::mean` |
| `torch.nn.MultiMarginLoss` | 训练/推理通用（`p=1` 或 `p=2`） | `Module.forward -> F.multi_margin_loss -> torch._C._nn.multi_margin_loss -> aten::multi_margin_loss -> AutogradCPU/CUDA` 包装并保存 `self/target/weight` `-> redispatch -> CPU/CUDA: multi_margin_loss_cpu / multi_margin_loss_cuda`；反向再走 `aten::multi_margin_loss_backward -> CPU/CUDA kernel` | `aten::multi_margin_loss`, `aten::multi_margin_loss_backward` |
| `torch.nn.MultiheadAttention` | 推理 fastpath（命中 `_native_multi_head_attention`，如 self-attn、`batch_first=True`、`eval/no_grad`） | `Module.forward -> torch._native_multi_head_attention -> aten::_native_multi_head_attention -> native_multi_head_attention_cpu / native_multi_head_attention_cuda`；CPU 常见实现内部为 `aten::matmul -> aten::bmm -> aten::_masked_softmax` 或 `aten::_softmax -> aten::bmm -> aten::linear`；CUDA 的 self-attn 且 `need_weights=False` 热路径可变成 `aten::linear -> aten::scaled_dot_product_attention -> aten::linear` | `aten::_native_multi_head_attention`, `aten::matmul`, `aten::bmm`, `aten::_masked_softmax`, `aten::_softmax`, `aten::linear`, `aten::scaled_dot_product_attention` |
| `torch.nn.MultiheadAttention` | 常规路径，`need_weights=False` | `Module.forward -> F.multi_head_attention_forward -> _in_projection_packed/_in_projection -> aten::linear`（packed QKV 或 3 次分投影）`-> aten::scaled_dot_product_attention -> {aten::_scaled_dot_product_flash_attention / aten::_scaled_dot_product_efficient_attention / aten::_scaled_dot_product_cudnn_attention / aten::_scaled_dot_product_attention_math}`；其中 math fallback 再展开为 `aten::matmul -> aten::_safe_softmax -> [aten::dropout] -> aten::matmul -> aten::linear` | `aten::linear`, `aten::scaled_dot_product_attention`, `aten::_scaled_dot_product_flash_attention`, `aten::_scaled_dot_product_efficient_attention`, `aten::_scaled_dot_product_cudnn_attention`, `aten::_scaled_dot_product_attention_math`, `aten::matmul`, `aten::_safe_softmax`, `aten::dropout` |
| `torch.nn.MultiheadAttention` | 常规路径，`need_weights=True` | `Module.forward -> F.multi_head_attention_forward -> aten::linear`（Q/K/V 投影）`-> aten::baddbmm`（有 mask）或 `aten::bmm`（无 mask）`-> aten::softmax -> [aten::dropout] -> aten::bmm -> aten::linear -> 可选 aten::mean(dim=head)` | `aten::linear`, `aten::baddbmm`, `aten::bmm`, `aten::softmax`, `aten::dropout`, `aten::mean` |
| `torch.nn.PixelUnshuffle` | 常规前向（CPU 原生 kernel；其他后端可走 composite fallback） | `Module.forward -> F.pixel_unshuffle(torch.pixel_unshuffle) -> aten::pixel_unshuffle -> Autograd` 包装后 redispatch；CPU 走 `pixel_unshuffle_cpu -> pixel_unshuffle_kernel`，无专门 kernel 的 fallback 走 `math_pixel_unshuffle -> aten::reshape -> aten::permute -> aten::clone -> aten::view` | `aten::pixel_unshuffle`, `aten::reshape`, `aten::permute`, `aten::clone`, `aten::view` |
| `torch.nn.PoissonNLLLoss` | `log_input=True`, `full=False` | `Module.forward -> F.poisson_nll_loss -> torch.poisson_nll_loss -> aten::poisson_nll_loss -> CompositeImplicitAutograd::native::poisson_nll_loss -> aten::exp -> aten::mul.Tensor -> aten::sub.Tensor -> aten::mean` | `aten::poisson_nll_loss`, `aten::exp`, `aten::mul.Tensor`, `aten::sub.Tensor`, `aten::mean` |
| `torch.nn.PoissonNLLLoss` | `log_input=False`, `full=True` | `Module.forward -> F.poisson_nll_loss -> torch.poisson_nll_loss -> aten::poisson_nll_loss -> CompositeImplicitAutograd::native::poisson_nll_loss -> aten::add.Scalar -> aten::log -> aten::mul.Tensor -> aten::sub.Tensor`；Stirling 分支再做 `aten::log / aten::le / aten::masked_fill / aten::add_`，最后 `aten::mean` | `aten::poisson_nll_loss`, `aten::add.Scalar`, `aten::log`, `aten::mul.Tensor`, `aten::sub.Tensor`, `aten::le`, `aten::masked_fill`, `aten::add_`, `aten::mean` |

## 备注

- `MultiLabelSoftMarginLoss` 与 `PoissonNLLLoss` 在当前仓库里都不是单一 fused backend loss kernel：前者是 Python 组合，后者是 `CompositeImplicitAutograd` 的 C++ 组合。
- `MultiheadAttention` 的 `_native_multi_head_attention` 在 autograd 层注册的是 `autogradNotImplementedFallback()`，所以训练时通常不会命中这个 fastpath。
- `PixelUnshuffle` 的反向公式在 `derivatives.yaml` 中直接写成 `pixel_shuffle(grad, downscale_factor)`。
