## 备注

1. **`torch.geqrf`**：QR 分解的底层 LAPACK 接口。功能型变体先分配两个 `aten::empty` 输出，再调用 `aten::geqrf.a`；最终通过 `geqrf_stub` 分发到 CPU (LAPACK `?geqrf_`) 或 CUDA (cuSOLVER)。functional 变体在 autograd 上注册为 `not_implemented("geqrf")`，out 变体则对 requires-grad 输入直接报错。dispatch key 为 `CPU, CUDA`。

2. **`torch.ger`**：已弃用的外积接口，直接委托给 `torch.outer`。`ger` 和 `ger.out` 在 YAML 中均无 dispatch key，属于 CompositeImplicitAutograd；autograd 通过 `aten::outer` → `aten::reshape` → `aten::mul` 的组合自动推导梯度。

3. **`torch.hamming_window`**：窗函数工厂方法，有 4 个重载（逐级补充默认参数）。dispatch key 为 CompositeExplicitAutograd，表示所有后端共享同一实现。最终前向链里实际出现的 ATen 接口是 `aten::empty` / `aten::ones` / `aten::arange` / `aten::mul_` / `aten::cos_` / `aten::add_` / `aten::narrow`；中间的 native 重载补默认参数不是额外 dispatch hop。

4. **`torch.hann_window`**：Hann 窗函数，实现为 `alpha=beta=0.5` 的 Hamming 公式特例。同为 CompositeExplicitAutograd dispatch；native 层直接复用同一套窗口构造逻辑，而不是额外经过一个新的 ATen dispatch hop。

5. **`torch.heaviside`**：Heaviside 阶跃函数，属于 structured op（基于 TensorIteratorBase）。`structured_delegate: heaviside.out` 只是 codegen 关系；运行时 `aten::heaviside`、`aten::heaviside.out`、`aten::heaviside_` 都各自有 wrapper，直接执行 `meta + impl`，随后由 `heaviside_stub` 落到具体 kernel。带 `pointwise` tag；无 `derivatives.yaml` 条目。
