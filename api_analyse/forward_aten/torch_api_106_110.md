# torch API 106-110 ATen Dispatch 分析

| 接口 | 场景 | ATen Dispatch 调用链 | 正向 Dispatch 依赖的 ATen 接口 |
| --- | --- | --- | --- |
| `torch.nn.LSTM` | CUDA 稠密输入，非 `PackedSequence`，显式提供 `hx/cx`，满足 cuDNN fast path | `torch.nn.LSTM.forward` -> `_VF.lstm` -> `aten::lstm.input` -> `CompositeImplicitAutograd`(`native::lstm`) -> `lstm_cudnn_stub` -> 真实 runtime hop `aten::_cudnn_rnn` -> `[requires_grad] AutogradCUDA`(`CudnnRnnBackward0`) -> CUDA backend -> `native::_cudnn_rnn`(cuDNN RNN) | `aten::lstm.input`<br>`aten::_cudnn_rnn` |
| `torch.nn.LSTMCell` | CUDA 单步输入，标准 dense 权重，走 fused cell 路径 | `torch.nn.LSTMCell.forward` -> `_VF.lstm_cell` -> `aten::lstm_cell` -> `CompositeImplicitAutograd`(`native::lstm_cell`) -> `aten::t` + `aten::matmul`(input/hidden 两路 gate GEMM) -> 真实 runtime hop `aten::_thnn_fused_lstm_cell` -> `[requires_grad] AutogradCUDA`(`ThnnFusedLstmCellBackward0`) -> CUDA backend -> `native::_thnn_fused_lstm_cell_cuda` | `aten::lstm_cell`<br>`aten::t`<br>`aten::matmul`<br>`aten::_thnn_fused_lstm_cell` |
| `torch.nn.LeakyReLU` | 非 inplace，稠密 CPU/CUDA，`input.requires_grad=True` | `torch.nn.LeakyReLU.forward` -> `F.leaky_relu` -> `torch._C._nn.leaky_relu` -> `aten::leaky_relu` -> `[requires_grad] AutogradCPU/CUDA/MPS`(`LeakyReluBackward0`) -> CPU/CUDA/MPS structured wrapper(`meta + impl`，由 `leaky_relu.out` schema 生成，不额外增加 runtime hop) -> `native::leaky_relu_out` -> `leaky_relu_stub` -> `leaky_relu_kernel_{cpu/cuda/mps}` | `aten::leaky_relu` |
| `torch.nn.MarginRankingLoss` | 1D mini-batch，`reduction='mean'`，`input1/input2.requires_grad=True` | `torch.nn.MarginRankingLoss.forward` -> `F.margin_ranking_loss` -> `torch.margin_ranking_loss` -> `aten::margin_ranking_loss` -> `CompositeImplicitAutograd`(`native::margin_ranking_loss`) -> `aten::sub` -> `aten::neg` + `aten::mul` -> `aten::add.Scalar` -> `aten::clamp_min_` -> `aten::mean` | `aten::margin_ranking_loss`<br>`aten::sub`<br>`aten::neg`<br>`aten::mul`<br>`aten::add.Scalar`<br>`aten::clamp_min_`<br>`aten::mean` |
| `torch.nn.MaxPool1d` | `return_indices=False`，训练/需要梯度，稠密 CPU/CUDA 输入 | `torch.nn.MaxPool1d.forward` -> `F.max_pool1d`(`boolean_dispatch` 默认分支) -> `torch.max_pool1d` -> `aten::max_pool1d` -> `CompositeImplicitAutograd`(`native::max_pool1d`) -> 真实 runtime hop `aten::max_pool1d_with_indices` -> `CompositeImplicitAutograd`(`native::max_pool1d_with_indices`) -> `aten::unsqueeze` -> 真实 runtime hop `aten::max_pool2d_with_indices` -> `[requires_grad] AutogradCPU/CUDA/MPS`(`MaxPool2DWithIndicesBackward0`) -> CPU/CUDA/MPS structured wrapper(`meta + impl`，由 `max_pool2d_with_indices.out` schema 生成，不额外增加 runtime hop) -> `native::max_pool2d_with_indices_out_{cpu/cuda/mps}` -> `max_pool2d_kernel`/CUDA kernel -> `aten::squeeze` | `aten::max_pool1d`<br>`aten::max_pool1d_with_indices`<br>`aten::unsqueeze`<br>`aten::max_pool2d_with_indices`<br>`aten::squeeze` |

## 备注

- `torch.nn.LSTM` / `torch.nn.LSTMCell` 的外层 `aten::lstm.*`、`aten::lstm_cell` 都是 `CompositeImplicitAutograd`；真正建立 `grad_fn` 的是被它们选中的内层实现，如 `aten::_cudnn_rnn`、`aten::_thnn_fused_lstm_cell`。
- `torch.nn.MaxPool1d` 在“需要梯度”的常见场景下不会停留在 `aten::max_pool1d` 直接 kernel，而是主动转到 `aten::max_pool1d_with_indices` / `aten::max_pool2d_with_indices` 以保存 indices。
