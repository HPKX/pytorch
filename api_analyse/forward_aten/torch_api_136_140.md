# torch API 136-140 ATen Dispatch 分析

| 接口 | 场景 | ATen Dispatch 调用链 | 正向 Dispatch 依赖的 ATen 接口 |
| --- | --- | --- | --- |
| `torch.nn.functional.celu` | 默认 `inplace=False` | `F.celu -> aten::celu -> [requires_grad 时 AutogradCPU/CUDA: VariableType::celu] -> CompositeExplicitAutograd(native::celu) -> aten::elu -> backend structured(meta -> impl) -> elu_stub -> backend elu_kernel` | `aten::celu`, `aten::elu` |
| `torch.nn.functional.celu` | `inplace=True` | `F.celu(inplace=True) -> aten::celu_ -> [requires_grad 时 AutogradCPU/CUDA: VariableType::celu_] -> CompositeExplicitAutograd(native::celu_) -> aten::elu_ -> backend structured(meta -> impl) -> elu_stub -> backend elu_kernel` | `aten::celu_`, `aten::elu_` |
| `torch.nn.functional.cosine_similarity` | 广播输入，且可能发生整型提升 | `F.cosine_similarity -> aten::cosine_similarity -> CompositeImplicitAutograd(native::cosine_similarity) -> aten::to(可选) -> aten::expand(广播) -> aten::linalg_vector_norm x2 -> aten::clone -> aten::scalar_tensor(eps) -> aten::clamp_min_ -> aten::div -> aten::mul -> aten::sum` | `aten::cosine_similarity`, `aten::to`, `aten::expand`, `aten::linalg_vector_norm`, `aten::clone`, `aten::scalar_tensor`, `aten::clamp_min_`, `aten::div`, `aten::mul`, `aten::sum` |
| `torch.nn.functional.ctc_loss` | 普通 fallback 路径（CPU，或 CUDA 但未走 cuDNN/MIOpen；`Tensor` lengths 的常规张量会先转 CPU `Long`） | `F.ctc_loss -> aten::ctc_loss.Tensor -> CompositeImplicitAutograd(native::ctc_loss) -> [Tensor fast path: lengths.to(cpu,long)] -> native::ctc_loss(IntList helper) -> native::ctc_loss_impl -> aten::_ctc_loss -> [requires_grad 时 AutogradCPU/CUDA: VariableType::_ctc_loss] -> CPU/CUDA kernel(ctc_loss_cpu/ctc_loss_gpu)` | `aten::ctc_loss.Tensor`, `aten::_ctc_loss` |
| `torch.nn.functional.ctc_loss` | CUDA 满足加速条件 | `F.ctc_loss -> aten::ctc_loss.Tensor -> CompositeImplicitAutograd(native::ctc_loss_impl) -> aten::_use_cudnn_ctc_loss / aten::_use_miopen_ctc_loss -> aten::_cudnn_ctc_loss / aten::miopen_ctc_loss -> [requires_grad 时 AutogradCUDA: VariableType::_cudnn_ctc_loss / miopen_ctc_loss] -> CUDA backend CTC kernel` | `aten::ctc_loss.Tensor`, `aten::_use_cudnn_ctc_loss`, `aten::_use_miopen_ctc_loss`, `aten::_cudnn_ctc_loss`, `aten::miopen_ctc_loss` |
| `torch.nn.functional.dropout1d` | 2D 非 batched，`training=True`（3D batched 同链路，只是没有 `unsqueeze/squeeze`） | `F.dropout1d -> aten::unsqueeze(仅2D) -> aten::feature_dropout / aten::feature_dropout_ -> CompositeImplicitAutograd(native::feature_dropout) -> _dropout_impl(feature=true) -> aten::new_empty -> aten::bernoulli_ -> aten::div_ -> aten::mul / aten::mul_ -> aten::squeeze(仅2D)` | `aten::unsqueeze`, `aten::feature_dropout`, `aten::feature_dropout_`, `aten::new_empty`, `aten::bernoulli_`, `aten::div_`, `aten::mul`, `aten::mul_`, `aten::squeeze` |
| `torch.nn.functional.dropout1d` | `training=False` 或 `p=0` | `F.dropout1d -> aten::feature_dropout / aten::feature_dropout_ -> CompositeImplicitAutograd(native::feature_dropout) -> _dropout_impl 直接返回输入，不再进入采样/缩放/乘法链` | `aten::feature_dropout`, `aten::feature_dropout_` |
| `torch.nn.functional.dropout2d` | 标准 4D 输入，`training=True` | `F.dropout2d -> aten::feature_dropout / aten::feature_dropout_ -> CompositeImplicitAutograd(native::feature_dropout) -> _dropout_impl(feature=true) -> aten::new_empty -> aten::bernoulli_ -> aten::div_ -> aten::mul / aten::mul_` | `aten::feature_dropout`, `aten::feature_dropout_`, `aten::new_empty`, `aten::bernoulli_`, `aten::div_`, `aten::mul`, `aten::mul_` |
| `torch.nn.functional.dropout2d` | 3D 输入的历史兼容路径 | `Python wrapper 先告警，然后仍调用 aten::feature_dropout / aten::feature_dropout_；后续 dispatch 与 4D 相同，本质上复用同一个 feature-dropout composite 实现` | `aten::feature_dropout`, `aten::feature_dropout_` |

## 备注

- `dropout1d` / `dropout2d` 走的是 `aten::feature_dropout`，不是 `aten::dropout`，因此不会进入 `native_dropout` / fused dropout 这条分发链。
- `cosine_similarity` 没有单独的 autograd kernel，梯度来自其内部展开的 `linalg_vector_norm`、`div`、`mul`、`sum` 等 ATen 算子。
- `celu` 自身是 `CompositeExplicitAutograd`，但真实数值计算会继续下钻到 structured `aten::elu`。
