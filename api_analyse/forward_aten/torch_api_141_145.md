# torch API 141-145 ATen Dispatch 分析

| 接口 | 场景 | ATen Dispatch 调用链 | 正向 Dispatch 依赖的 ATen 接口 |
| --- | --- | --- | --- |
| `torch.nn.functional.dropout3d` | 5D 输入，`training=True`，`inplace=False` | `F.dropout3d` -> `aten::feature_dropout` (`CompositeImplicitAutograd`) -> `at::native::feature_dropout` -> `aten::new_empty`（生成按 channel broadcast 的噪声）-> `aten::bernoulli_` -> `aten::div_` -> `aten::mul` | `aten::feature_dropout`, `aten::new_empty`, `aten::bernoulli_`, `aten::div_`, `aten::mul` |
| `torch.nn.functional.dropout3d` | 4D 输入（无 batch 维），`training=True` | `F.dropout3d` -> `aten::unsqueeze` -> `aten::feature_dropout`（后续同 5D 场景）-> `aten::new_empty` -> `aten::bernoulli_` -> `aten::div_` -> `aten::mul` -> `aten::squeeze.dim` | `aten::unsqueeze`, `aten::feature_dropout`, `aten::new_empty`, `aten::bernoulli_`, `aten::div_`, `aten::mul`, `aten::squeeze.dim` |
| `torch.nn.functional.gaussian_nll_loss` | `var` 比 `input` 少 1 维需广播，`full=False`，`reduction='mean'` | `F.gaussian_nll_loss` -> `aten::unsqueeze`（广播补维）-> `aten::clone` -> `torch.no_grad()` 下 `aten::clamp_` -> `aten::log` + `aten::sub.Tensor` + `aten::pow.Tensor_Scalar` + `aten::div.Tensor` + `aten::add.Tensor` + `aten::mul.Scalar` -> `aten::mean` | `aten::unsqueeze`, `aten::clone`, `aten::clamp_`, `aten::log`, `aten::sub.Tensor`, `aten::pow.Tensor_Scalar`, `aten::div.Tensor`, `aten::add.Tensor`, `aten::mul.Scalar`, `aten::mean` |
| `torch.nn.functional.gumbel_softmax` | `hard=False`（soft sample） | `F.gumbel_softmax` -> `aten::empty_like` -> `aten::exponential_` -> `aten::log` -> `aten::neg` -> `aten::add.Tensor` -> `aten::div.Scalar` -> `aten::softmax.int` (`CompositeImplicitAutograd`) -> `at::native::softmax` -> `aten::_softmax` -> `AutogradCPU/CUDA` -> CPU/CUDA structured wrapper（`meta` + `impl`） | `aten::empty_like`, `aten::exponential_`, `aten::log`, `aten::neg`, `aten::add.Tensor`, `aten::div.Scalar`, `aten::softmax.int`, `aten::_softmax` |
| `torch.nn.functional.gumbel_softmax` | `hard=True`（straight-through） | `F.gumbel_softmax` 先走 soft 路径：`aten::empty_like -> aten::exponential_ -> aten::log -> aten::neg -> aten::add.Tensor -> aten::div.Scalar -> aten::softmax.int -> aten::_softmax`，随后 `aten::max.dim` -> `aten::zeros_like` -> `aten::scatter_.value` -> `aten::detach` -> `aten::sub.Tensor` -> `aten::add.Tensor` | `aten::empty_like`, `aten::exponential_`, `aten::log`, `aten::neg`, `aten::add.Tensor`, `aten::div.Scalar`, `aten::softmax.int`, `aten::_softmax`, `aten::max.dim`, `aten::zeros_like`, `aten::scatter_.value`, `aten::detach`, `aten::sub.Tensor`, `aten::add.Tensor` |
| `torch.nn.functional.hardtanh` | 默认 `inplace=False`，`requires_grad=True` | `F.hardtanh` -> `aten::hardtanh` -> `AutogradCPU/CUDA` -> CPU/CUDA wrapper -> `at::native::hardtanh` -> `aten::clamp.out` -> CPU/CUDA structured wrapper（`meta` + `impl`/TensorIterator） | `aten::hardtanh`, `aten::clamp.out` |
| `torch.nn.functional.hinge_embedding_loss` | `target` 含 `±1`，`reduction='mean'` | `F.hinge_embedding_loss` -> `aten::hinge_embedding_loss` (`CompositeImplicitAutograd`) -> `at::native::hinge_embedding_loss` -> `aten::zeros_like` -> `aten::sub.Scalar` -> `aten::clamp_min_`（Forward AD/CCT 场景下改走 `aten::clamp_min`）-> `aten::where` + `aten::where` -> `aten::add.Tensor` -> `aten::mean` | `aten::hinge_embedding_loss`, `aten::zeros_like`, `aten::sub.Scalar`, `aten::clamp_min_`, `aten::clamp_min`, `aten::where`, `aten::add.Tensor`, `aten::mean` |

## 备注

- `gaussian_nll_loss` 与 `gumbel_softmax` 都是 Python 组合实现，没有单独的 `aten::gaussian_nll_loss` / `aten::gumbel_softmax` 入口。
- `gumbel_softmax(hard=True)` 的 straight-through 关键在 `aten::detach`：前向值来自 `scatter_` 生成的 one-hot，反向仍回到 `softmax` 分支。
- `hardtanh` 虽然从 `aten::hardtanh` 入口进入，但前向真正的计算 hop 落到 `aten::clamp.out`；专用 backward 才是 `aten::hardtanh_backward`。
